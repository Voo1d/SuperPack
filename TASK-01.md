Прочитай README.md и CLAUDE.md; посмотри prototype/index.html и prototype/app.js. Начни реализацию SuperPack в этой папке. Это первый этап, поэтому доведи до работающего сквозного сценария, а не только до каркаса.

Задача этапа:
1. Создай проект frontend (React + TypeScript + Vite), backend (NestJS + TypeScript), PostgreSQL + Drizzle, Docker Compose для локальной БД, миграции, .env.example и команды запуска в README. Зафиксируй совместимые версии и lockfile. В корне нужен ARM64-совместимый Dockerfile для одного контейнера приложения: собранный React и API с одного origin, прослушивание 0.0.0.0:$PORT (по умолчанию 8000), GET /health, команда npm run migrate. Сервер dev-деплоя сам даёт DATABASE_URL и PORT, базу в образ приложения не добавляй.
2. Реализуй проверку подписанного Telegram Mini App initData на сервере, поиск сотрудника по Telegram ID и запрет доступа по умолчанию. Первого администратора задай через серверную переменную окружения. Админ может разрешить, заблокировать и назначить роль сотруднику. Отдельный локальный dev-режим допустим только при явном включении, без произвольного доверия клиентскому ID.
3. Создай таблицы/модели номенклатуры, партий, складских движений и сотрудников. Сделай API приёмки партии и просмотра склада с категориями «Готовая продукция», «Сырьё», «Запчасти», «Другое», фильтром и историей партии. Валидируй данные на сервере, обеспечь уникальность кода партии и корректные остатки.
4. Перенеси визуальный стиль прототипа для экранов склада и приёмки, подключи их к API. Остальные экраны можно оставить заглушками с ясной пометкой; не показывай демоданные как реальные остатки.
5. Добавь необходимые тесты: поддельные/устаревшие initData, закрытый доступ, приёмка и создание движения, повтор кода партии, отрицательное количество. Выполни миграции и тесты; запусти локально и проверь реальный сценарий: админ открывает доступ, сотрудник принимает партию, она отображается в своей категории с историей.

Не проси меня выбирать мелкие технические детали — решай их и кратко записывай. Если для запуска нужен реальный токен бота, оставь переменную и покажи локальный dev-сценарий без него. Не выдумывай мои Telegram ID и токены. По завершении перечисли сделанное, команды для запуска и проверки, известные ограничения и вопросы только о бизнес-правилах, без ответа на которые следующий этап нельзя реализовать правильно. Работай в отдельной ветке; подготовь проверяемый коммит и PR в `dev`. Не меняй настройки VM или существующего бота из этого репозитория.
